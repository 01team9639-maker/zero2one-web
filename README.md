# ZERO 2 ONE — Marketing Agency Website

Marketing website for **ZERO 2 ONE**, a Riyadh-based digital marketing agency.
Static, animation-driven site (no backend / build step) with a bilingual
English ⇄ Arabic layer and a small Python audit toolkit under [`tools/`](tools/).

> **Tagline:** *from zero to one* — web design, SEO, advertising, brand
> identity, social media, and e-commerce.

---

## Tech stack

| Concern            | Library / approach |
|--------------------|--------------------|
| Page transitions   | [barba.js](https://barba.js) (`sync` AJAX, swaps `<main>`) |
| Smooth scroll      | locomotive-scroll |
| Animation          | GSAP + ScrollTrigger |
| Lazy loading       | vanilla-lazyload |
| Fonts              | Neue Montreal / *Dennis Sans* (local) + **Cairo** (Google, Arabic) |
| i18n               | **build-time** — real `/ar/` pages generated by [`tools/build_ar.py`](tools/build_ar.py) |
| Analytics          | GTM + GA4 (gtag), `generate_lead` conversion events |

All third-party JS is loaded from public CDNs (jsDelivr / cdnjs / jQuery CDN).

All asset and page links are **root-absolute** (`/assets/…`, `/services/seo-riyadh/`)
so the same markup works at any directory depth — which is what lets `/ar/` be a
straight mirror of the English tree.

`style-new.css` holds all the project-specific styling (mobile rules, the
Arabic/RTL block, service-page/testimonial cards, contact form, etc.). The other
CSS files are the original template layers.

> **URL history.** The six service pages used to live at
> `/pages/projects/<name>.html`. They moved to `/services/<slug>/` in July 2026;
> the permanent 301s in [`.htaccess`](.htaccess) carry the indexing across and
> must not be removed.

## Running locally

It's fully static — serve the folder with any static server:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

Opening `index.html` via `file://` mostly works but a server is recommended
(barba fetches pages over HTTP).

## Bilingual — English at `/`, Arabic at `/ar/`

Arabic is **not** a runtime DOM translation any more. Every Arabic page is real
static HTML with its own URL, `<title>`, meta description and JSON-LD, paired
with its English twin through `<link rel="alternate" hreflang>`. That is the
only form a search engine can crawl, index and rank.

### Editing content

1. Edit the **English** page (the source of truth).
2. Add/adjust translations in [`tools/ar-dictionary.json`](tools/ar-dictionary.json)
   — keys are the exact English text.
3. Regenerate:

```bash
python3 tools/build_ar.py --missing   # lists English text with no translation yet
python3 tools/build_ar.py             # writes the whole /ar/ tree
python3 tools/generate_sitemap.py     # refresh sitemap (EN + AR + hreflang)
```

**Never hand-edit anything under `/ar/`** — the next build overwrites it.
Arabic `<title>` / description / keywords per page live in `AR_META` inside
`tools/build_ar.py`; markup built from several `<span>`s (the hero, the footer
headline, the logo label) is handled by `HTML_REPLACEMENTS` in the same file.

### At runtime

[`assets/js/i18n.js`](assets/js/i18n.js) is now just a ~40-line router:

- `?lang=ar` / `?lang=en` — explicit override, either direction, remembered in
  `localStorage`,
- an Arabic-preferring device landing on an English page is sent to its `/ar/`
  counterpart once (target read from the page's own `hreflang` tag),
- an Arabic page is **never** auto-redirected to English — `/ar/` URLs are
  indexed and shared,
- the `العربية / English` switcher in the nav and side menu is a plain link
  carrying `data-barba-prevent`, so the language change is a full page load and
  `<html lang/dir>` flips correctly.

CSS direction fixes live in the **Arabic / RTL** block at the end of
`style-new.css`, keyed off `body.lang-ar`.

## SEO

Every page ships with: a unique `<title>` + meta description, canonical URL,
`hreflang` alternates (`en` / `ar` / `x-default`), Open Graph + Twitter cards,
`theme-color`, and JSON-LD structured data. `robots.txt` + `sitemap.xml` are
present and validated.

A few structural rules worth keeping:

- **One `<h1>` per page, and it describes the service — not the brand.** The
  home page `<h1>` is *"Digital Marketing Agency in Riyadh"*; the big
  `ZERO 2 ONE —` wordmark in the hero is a decorative `div.brand-wordmark`.
- **The loading screen contains no headings.** Its animated words are
  `div.loading-word`, so *Hello / Bonjour / Ciao…* never enter the heading
  outline ahead of the real page heading.
- **Conversion tracking.** Every contact action (WhatsApp, phone, email, contact
  form) fires a GA4 `generate_lead` event with the channel in `method` —
  see `initLeadTracking()` in `assets/js/index-new.js`. Mark it as a key event
  in GA4 → Admin → Events.

## GEO / AEO (AI answer engines)

Beyond classic SEO, the site is tuned to be **understood and cited by
generative / answer engines** (ChatGPT, Claude, Perplexity, Gemini, Google AI
Overviews):

- **Rich structured data** — an `@graph` of `ProfessionalService`
  (with an `OfferCatalog` of all six services, full NAP, `sameAs`) and
  `WebSite` on the home page; `Service` + `BreadcrumbList` on each service page;
  and an **`FAQPage`** backed by a **visible FAQ section** (direct answers are
  what AI Overviews quote).
- **[`llms.txt`](llms.txt)** — an LLM-friendly summary of the agency, services
  and contact details (the emerging GEO standard).
- **[`robots.txt`](robots.txt)** — explicitly welcomes AI crawlers (GPTBot,
  OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended, Applebot-Extended,
  CCBot…).

Both are verified by the toolkit:

```bash
python3 tools/audit.py          # SEO / code audit          (0 errors = clean)
python3 tools/geo_audit.py      # GEO / AEO / AIO readiness  (verdict: EXCELLENT)
python3 tools/check_links.py    # broken-link report
```

The full toolkit — audits, link check, robots validator, sitemap generator,
image/CDN prep — is documented in **[`tools/README.md`](tools/README.md)**.

### ⚠️ Before going live — configure these

| Item | Where | Note |
|------|-------|------|
| **Domain** | canonical / `og:url` / `sitemap.xml` / `robots.txt` | Currently assumes `https://zero2one.sa`. If the real domain differs, re-run `tools/generate_sitemap.py --base https://REAL_DOMAIN` and update the `<head>` URLs. |
| **Opening hours** | `openingHoursSpecification` in `index.html` schema, `/contact/` page | Set to Sun–Thu 09:00–18:00. Confirm before launch. |
| **Map coordinates** | `LocalBusiness` schema | `hasMap` points at the Google Maps place; a `geo` lat/long pair should be added once confirmed (do not guess it). |
| **Contact form** | `action` on `#contact-form`, `/contact/` | Posts to Formspree form `xqedjevn`. Verify that endpoint belongs to the agency's account and that the notification email is right. |
| **Search Console** | — | Submit `sitemap.xml`, and use *Change of Address / URL Inspection* to re-crawl the six moved service URLs. |
| **Share image** | `og:image` | Uses `assets/images/about-us-zero2one.png` (portrait). A dedicated 1200×630 landscape image is recommended. |

## Images & CDN

Source images are heavy PNGs. `tools/optimize_images.py` generated **WebP**
copies next to each one (**≈92 % smaller — 26 MB → 2.2 MB**) and losslessly
re-compressed the PNGs.

To actually serve the savings, pick one:

1. **CDN auto-format (recommended, zero markup change).** Put Cloudflare
   (enable *Polish → WebP*) or Bunny (*Optimizer*) in front of the origin. The
   CDN converts/upgrades images per request; the existing `assets/images/*.png`
   URLs keep working.
2. **`<picture>` element.** Reference the generated `.webp` with a PNG
   fallback:
   ```html
   <picture>
     <source srcset="assets/images/service-1.webp" type="image/webp">
     <img src="assets/images/service-1.png" alt="…">
   </picture>
   ```
3. **Point assets at a CDN host.** If assets live on a CDN subdomain, rewrite
   `assets/…` references to `https://cdn.zero2one.sa/assets/…` at deploy time.

Regenerate anytime: `python3 tools/optimize_images.py --png`
(add `--max-width 1920` to also cap oversized sources).

## Deployment

Any static host works (Netlify, Vercel, Cloudflare Pages, S3+CloudFront, Nginx).
Deploy the repo root as-is. Recommended headers/CDN settings:

- long-cache `assets/**` (fingerprint or cache-bust on change),
- enable Brotli/Gzip for HTML/CSS/JS,
- enable image auto-format (see above),
- serve over HTTPS (canonical URLs are `https://`).
